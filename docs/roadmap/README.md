# 구현 로드맵

## 이 로드맵이 겨냥하는 것

`CLAUDE.md`의 3개월 성공 기준은 콘텐츠 개수가 아니라 **개선 루프가 한 바퀴 돌았다는 사실**이다.

> (필수) 사용자 신호가 집계되어 뼈대 수정을 트리거한 사례가 존재한다

로드맵의 순서는 전부 이 한 문장에서 역산했다. 루프가 한 바퀴 돌려면 **신호가 있어야** 하고,
신호가 있으려면 **소비가 있어야** 하고, 소비가 있으려면 **published 뼈대가 있어야** 하고,
뼈대가 하나로 모이려면 **주제 매핑이 먼저** 있어야 한다.

## 크리티컬 패스

```
M0  기반 골격과 CI
 │
 ▼
M1  카탈로그 · 주제 매핑          ← 신호를 한 뼈대에 모으는 전제조건
 │
 ▼
M2  뼈대 생성 파이프라인          ← 소비할 대상이 생긴다
 │
 ▼
M3  학습 경험 (웹)                ← ★ 여기서 신호가 처음 발생한다
 │
 ├──────────────┬───────────────────────────┐
 ▼              ▼                           ▼
M4 개인 루프   M5 집단 루프 ★            M6 딜리버리 확장
               (3개월 필수 기준)          (영상 · PPT)
                │                           │
                └────────────┬──────────────┘
                             ▼
                        M7 운영 성숙
```

**크리티컬 패스는 `M0 → M1 → M2 → M3 → M5`다.** M4와 M6는 필수 기준 밖이므로, 일정이 밀리면
여기를 먼저 미룬다. M6는 M3 이후 언제든 병행할 수 있다.

## 이 로드맵이 전제하는 결정

로드맵을 순서로 세우는 순간, `CLAUDE.md`의 미결정 항목 중 하나가 자동으로 결정된다. 숨기지 않고
명시한다.

### 딜리버리 형태 우선순위 — 웹 먼저, 영상·PPT는 M6

`CLAUDE.md`의 "아직 정하지 않은 것"에 있던 **딜리버리 형태별 우선순위**를 이 로드맵은 *웹 우선*
으로 놓는다. 근거는 3개월 필수 기준이 **집단 루프 1회전**이지 딜리버리 다양성이 아니기 때문이다.
영상·PPT를 M2에 넣으면 첫 신호가 발생하는 시점이 TTS·렌더링 구축만큼 뒤로 밀리는데, 그 지연은
필수 기준에 아무것도 기여하지 않는다.

다만 이것이 **"전 형태를 사전 생성해야 published"** 원칙을 깨서는 안 된다. 그러면 "뼈대는 항상
완결 상태"라는 일괄 생성의 근거 자체가 무너진다. 그래서 published 조건을 다음과 같이 읽는다.

> published = **활성화된 형태 전부**에 대해 전 챕터 생성 완료

M2~M5 구간에서는 활성 형태가 `web` 하나이므로 조건이 그대로 성립하고, M6에서 `video`·`pptx`를
활성화하면 조건이 자동으로 확장된다. **형태를 나중에 켠다**는 것이지 완결성을 포기한다는 뜻이
아니다.

> 이 결정이 확정되면 `CLAUDE.md`의 미결정 목록에서 해당 항목을 지우고 본문에 반영해야 한다.
> (문서 갱신 규칙 2번)

## 로드맵을 이렇게 자른 이유

**M1(주제 매핑)을 M2(생성)보다 앞에 뒀다.** 생성이 더 눈에 보이는 성과지만, 매핑 없이 생성부터
만들면 초기 뼈대가 중복 주제로 갈라진 채 쌓이고 나중에 병합해야 한다. 주제 통합은 부가 기능이
아니라 개선 루프의 전제조건이라고 `CLAUDE.md`가 못박은 그대로다.

**M3(소비)와 M5(집단 루프) 사이에 M4(개인 루프)를 끼우지 않았다.** 둘은 같은 신호를 쓰지만 필수
기준에 기여하는 쪽은 M5뿐이다. M4를 먼저 하면 필수 기준 도달이 그만큼 늦어진다.

**M7(운영 성숙)을 마지막에 뒀지만 시드 카탈로그는 M3에 있다.** 운영자 도구 전체는 뒤로 미룰 수
있어도, 소비할 콘텐츠가 없으면 신호가 발생하지 않는다. 시드는 도구가 아니라 **신호의 재료**다.
