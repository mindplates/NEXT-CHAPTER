## 목표

**주제가 확정되면 비동기로 전 범위를 생성해 `published` 뼈대를 만든다.**

이 마일스톤이 끝나면 소비할 대상이 생긴다. M3의 신호는 전부 여기서 만든 콘텐츠에 붙는다.

## 완료 기준 (DoD)

- [ ] 주제 1개가 비동기 잡으로 전 챕터 생성되어 `published` 상태가 된다
- [ ] 챕터 하나가 실패하면 N회 재시도 후 운영자 큐로 가고, 뼈대는 `published`로 넘어가지 않는다
- [ ] Postgres에 커밋된 챕터가 outbox를 거쳐 Neo4j에 **빠짐없이** 반영된다 (재시도 안전)
- [ ] 뼈대당 또는 일일 비용 상한을 넘으면 생성이 중단되고 알림이 간다
- [ ] 챕터를 수정하면 새 버전이 스냅샷으로 쌓이고 이전 버전이 남는다

## 페이즈

### P2.1 블록 문서 모델과 챕터 버저닝

- [ ] 딜리버리 중립 블록 문서 — `heading / paragraph / figure / formula / narration / quiz`
- [ ] 블록마다 타입 + **안정적인 ID**
- [ ] `chapter_versions` 전체 스냅샷 저장 (델타 아님)
- [ ] **블록 ID 생성·승계 규칙 확정**

> 블록 ID 승계 방식을 M5까지 미루면 그때 전면 수정이 된다. 이 시점에 규칙을 정하고, 실제로
> 이어지는지의 **검증**만 M5 P5.7로 넘긴다. 규칙 없이 생성부터 시작하면 이미 쌓인 콘텐츠의
> ID를 나중에 다시 매길 방법이 없다.

### P2.2 잡 상태 머신과 Kafka 토픽 체인

- [ ] 상태: `generating_graph → generating_outlines → generating_bodies → generating_assets → published`
- [ ] 토픽: `skeleton.graph.requested` → `skeleton.outline.requested` → `skeleton.body.requested`
- [ ] **토픽 네이밍 · 파티션 전략 확정**
- [ ] 잡 진행률 조회 API (완료 알림의 재료)

M2에서 활성 형태는 `web` 하나이므로 `generating_assets`는 이미지·도표까지만 돈다. 영상·PPT
토픽은 M6에서 붙인다.

### P2.3 ① 그래프 생성

- [ ] 챕터 제목 · 요약 · 챕터 간 관계 생성
- [ ] 선형 목차가 아닌 **그래프**로 저장

### P2.4 ② 개요 생성

- [ ] 챕터별 개요 생성
- [ ] 챕터 간 **중복 · 누락 검사**

호출 횟수와 대기시간이 늘지만, 중복·누락을 본문 생성 **전에** 잡는 편이 훨씬 싸다.

### P2.5 ③ 본문 생성

- [ ] 챕터 수만큼 메시지 발행 (파티션으로 병렬도 조절)
- [ ] 블록 문서 생성
- [ ] 챕터별 **독립 재시도**
- [ ] 핵심 주장에 출처 근거 생성

### P2.6 Transactional Outbox → Neo4j

- [ ] Postgres 트랜잭션 안에서 본문·버전과 outbox를 **같은 커밋**으로
- [ ] 퍼블리셔 → Kafka
- [ ] Neo4j 어댑터가 **멱등** 소비 (멱등 키 = 챕터 ID + 버전)
- [ ] Neo4j에는 챕터 ID · 관계 · 임베딩만 (얇은 그래프)

분산 트랜잭션이 없으므로 순차 쓰기 + 보상은 프로세스가 죽는 구간에서 불일치를 남긴다.

### P2.7 비용 상한

- [ ] 뼈대당 상한 · 일일 전체 예산 상한 (둘 다 관리 화면 설정값, 무제한 허용)
- [ ] 초과 시 생성 중단 + 알림
- [ ] **Batch API** 적용 — 비동기 일괄이므로 조건에 부합, 전 토큰 50% 할인

### P2.8 실패 처리

- [ ] N회 자동 재시도
- [ ] 실패 항목을 운영자 큐로
- [ ] **전 챕터 · 활성 전 형태 성공 시에만** `published`

부분 공개를 허용하면 그래프 탐색 · 신호 집계 · 수정 루프 **전부에** "일부 챕터 없음" 분기가 생긴다.
일괄 생성을 택한 근거 자체가 "뼈대는 항상 완결 상태"였다.

## 여기서 정해야 할 것

| 항목 | 비고 |
|------|------|
| Kafka 토픽 네이밍 · 파티션 전략 | P2.2 |
| 블록 ID 생성 · 승계 규칙 | P2.1 — 검증은 M5 P5.7 |
| 자동 재시도 횟수 | P2.8 |
| 뼈대 하나의 실제 생성 단가 | 측정치가 M7의 검증 패스 범위 결정에 쓰인다 |

## 리스크

| 리스크 | 대응 |
|--------|------|
| 생성 단가를 모른 채 상한을 정하면 상한이 무의미해진다 | P2.7 전에 주제 1개를 끝까지 돌려 실측 |
| Batch API의 최대 24시간 지연 | 첫 소비까지 시간이 걸리는 것은 이미 감수한 대가. 잡 진행률 조회로 노출 |
| outbox 퍼블리셔가 밀리면 그래프 탐색이 빈 노드를 본다 | `published` 전환 조건에 Neo4j 반영 완료를 포함 |
