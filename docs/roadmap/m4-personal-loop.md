## 목표

**방금 답한 결과가 다음 챕터에 즉시 반영된다.**

일정이 밀리면 [M5](m5-collective-loop.md)보다 먼저 미루는 마일스톤이다. 같은 신호를 쓰지만 필수
기준에 기여하는 쪽은 M5다.

## 완료 기준 (DoD)

- [ ] 이해도가 다른 두 사용자가 같은 뼈대·같은 진입점에서 **서로 다른 경로**를 받는다
- [ ] 막힌 지점에 보충 블록이 삽입되고, **본문 블록은 바뀌지 않는다**
- [ ] 같은 챕터라도 사용자별로 퀴즈 난이도가 다르다
- [ ] 뼈대가 수정돼도 개인 학습 기록이 살아남는다 (챕터 ID 기준)

## 페이즈

### P4.1 사용자 레이어 저장

- [ ] 응답 · 퀴즈 결과 · 질문을 **챕터 ID 기준**으로 축적
- [ ] 뼈대 버전이 올라가도 레이어가 유지되는지 확인

### P4.2 경로 개인화

- [ ] 그래프에서 다음에 볼 챕터를 이해도 · 관심에 맞춰 선택
- [ ] 개인 루프는 **동기 읽기** — Postgres에서 곧바로

### P4.3 보충 블록

- [ ] 막힌 지점에 추가 설명 · 예시를 **삽입**
- [ ] 본문 블록은 읽기 전용 — 수정 경로 자체를 만들지 않는다
- [ ] 생성 단계는 AI 프로바이더 설정의 "개인화 보충 블록"을 따른다

> 보충 블록이 본문을 고치기 시작하면 집단 루프가 무너진다. 여러 사람이 각자 다른 텍스트를 봤다면
> "같은 지점에서 틀렸다"를 비교할 수 없고, 그 비교가 이 제품의 핵심 메커니즘이다. 삽입만 가능한
> 구조로 **강제**한다 — 규칙으로 두면 언젠가 깨진다.

### P4.4 퀴즈 난이도 조절

- [ ] 같은 챕터에서 문항 난이도를 사용자별로 조절
- [ ] 난이도가 집단 신호 집계를 오염시키지 않도록 신호에 난이도를 함께 기록

### P4.5 캐시 경계 정리

- [ ] 공용 블록 문서는 `chapter:{id}:v{version}:{format}` 캐시
- [ ] 개인화된 합성 결과는 캐시 대상이 아님 — 경계를 코드로 분리

## 여기서 정해야 할 것

| 항목 | 비고 |
|------|------|
| 이해도 산출 방식 | 퀴즈 정답률만 볼지, 질문 빈도·소비 속도를 섞을지 |
| 보충 블록 생성 시점 | 요청 시 즉시 생성 vs 사전 생성 후 선택 |

## 리스크

| 리스크 | 대응 |
|--------|------|
| 난이도 개인화가 집단 신호의 오답률을 흐린다 | 신호에 난이도를 기록하고, M5 임계치 판정에서 보정 |
| 보충 블록을 조회마다 생성하면 비용이 사용자 수 × 조회 수로 늘어난다 | 레이어에 캐시. 위 "정해야 할 것" 2번과 함께 결정 |
